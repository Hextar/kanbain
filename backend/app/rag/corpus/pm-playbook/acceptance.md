# Acceptance criteria

Every leaf task needs acceptance criteria a skeptical reviewer could check without the author in the room.

Write criteria as observable outcomes: a screen exists, an API returns, a risk is logged, a test fails red then goes green.

Avoid criteria that restated the title. Avoid "done when it looks good."

Stories can omit leaf-level criteria only when every child task already has them. Epics describe the outcome; leaves prove it.
